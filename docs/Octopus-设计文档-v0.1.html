一、这个 App 解决什么问题

孩子做完作业或试卷后，错题散落在纸上。想整理成错题集，通常要手抄一遍——费时、字丑、还容易抄错。

Octopus 要做的就是：

拍几张照片 → 自动切出每道错题 → 去掉孩子写过的笔迹，还原成干净的新题 → 挑出来打印成一张练习卷。

核心价值是省掉手抄，并且能反复重做。

目标用户

角色用法
家长（主要）拍试卷、整理、挑题、打印
孩子做打印出来的练习卷

典型场景

  1. 日常录入：孩子作业本上有 5 道错题 → 拍照 → 自动切题 → 存入错题库
  2. 考前复习：从错题库里按学科/知识点挑 20 道 → 生成练习卷 → 打印
  3. 重做：孩子做完了 → 再拍一次 → 标注是否掌握

二、功能清单

按优先级分三档：P0 必须有 / P1 应该有 / P2 锦上添花

录入

优先级功能
P0拍照 / 从相册导入
P0手动框选切出题目区域（一张卷子可切多道）
P0每道题填学科、来源、日期
P1自动切题：自动识别一张卷子里的多道题并预切分
P1一页多题批量录入
P2连续拍照（不退出相机，连拍多张）

题目清理（这是重点）

优先级功能
P0OCR 识别题干文字
P0编辑题干文本（可删掉孩子写的答案、划掉的内容）
P0按编辑后的文本重新排版成干净题目
P1手动擦除：手指涂抹去掉图片上的手写痕迹
P1保留原图区域（图形题、公式题不重建，直接用原图）
P2自动检测手写笔迹并擦除（图像修复）

为什么这样设计：用户说的"上面划掉很多东西，重新修改成一个新的题目"，

最可靠的实现是文本重建——OCR 出印刷体文字，用户在文本里删掉多余内容，

再排版输出。图像修复（把笔迹擦掉）技术上可行但效果不稳定，作为辅助手段。

错题库

优先级功能
P0列表浏览（缩略图 + 题干摘要）
P0多选
P0按学科 / 时间筛选
P1搜索（题干关键词）
P1标签 / 知识点
P1标注掌握状态（未掌握 / 复习中 / 已掌握）
P2统计（各科错题数、知识点分布）

变式题（同类题）

优先级功能
P1选中一道题 → AI 生成 N 道同知识点、同难度的变式题
P1生成的题可编辑、可保存进错题库
P2一次给多道题批量生成变式

打印

优先级功能
P0选中的题 → 排版 → 导出 PDF
P0调用系统打印（Android 打印框架）
P1版式选项：每题答题空间大小、是否显示题号/姓名/日期
P1可选附答案页
P2保存为常用的"练习卷模板"

四、数据模型

Question（错题）
├─ id
├─ 原始图片路径         裁剪后的题目图
├─ 重建后的图片路径      重排后的干净题目（可空，空则用原图）
├─ 题干文本            OCR + 人工编辑后的结果
├─ 题型                纯文字 / 含图形 / 含公式 / 含表格
├─ 学科                数学 / 语文 / 英语 / 物理 …
├─ 知识点标签[]         "一元二次方程"、"古诗词默写" …
├─ 难度                1-5
├─ 来源                哪张卷子 / 什么作业
├─ 掌握状态            未掌握 / 复习中 / 已掌握
├─ 变式题关系[]         与原题的关联
├─ 创建时间 / 最后复习时间
└─ 复习次数

Worksheet（练习卷）
├─ id
├─ 名称
├─ 题目列表[Question.id] + 顺序
├─ 版式设置            答题空间 / 是否显示题号 / 是否附答案
├─ 导出的 PDF 路径
└─ 创建时间

Source（来源，可选）
├─ id
├─ 名称                如"第三单元测试"
├─ 日期
└─ 照片原图

五、技术选型

总体

项选择理由
框架Flutter你已有 Spark/Flick 的完整工具链和经验（JDK17 + Flutter 3.47.6 + Gradle 8.14 都已配好）
平台Android（minSdk 26）你的要求
状态管理Riverpod与 Spark 一致，你熟悉
本地存储SQLite（drift 或 sqflite）+ 图片存文件系统离线可用
打印pdf + printing 包一套代码同时支持导出 PDF 和系统打印

分能力选型

能力推荐方案备选说明
OCR 文字识别PaddleOCR（本地）百度/腾讯 OCR API本地可离线、免费；中文印刷体准确率很高；模型约 10–20MB
版面分析（自动切题）PaddleOCR 的 PP-Structure自研投影法切分能识别文字块/图片块/表格
手写擦除手动涂抹（OpenCV inpaint）自研手写检测自动检测不可靠，先用手动
公式识别图像区域直接保留Mathpix API / pix2tex通用 OCR 对公式很差，见下方风险
变式题生成LLM API（DeepSeek / 通义 / 豆包）本地小模型需要联网 + API key

一个关键取舍：本地 vs 云端

方案优点缺点
全本地隐私最好、无费用、离线可用公式识别和大模型做不到
全云端效果最好孩子作业照片上传到第三方，隐私顾虑；持续费用
混合（推荐）照片本地处理，只有生成变式题时上传文本需联网才能生成变式题

建议选混合：OCR、切题、擦除全在本地跑；只有"生成同类题"这一步调用 LLM，

而且只上传题干文本，不上传图片。这样孩子的作业照片不会离开设备。

六、技术难点与应对

难点 1：自动切题不一定准 ⚠️ 高风险

试卷版面千变万化——横排、分栏、图形题、表格。全自动切分一定有错。

应对：

  • 自动切分只作为预切分，切完立刻让用户手动调整（拖动边框、合并、拆分）
  • 手动框选（P0）先做扎实，自动切题（P1）后面再加
  • 宁可"切得保守"（多切几块让用户合并）也不要漏题

难点 2：去掉手写笔迹 ⚠️ 高风险

用户的核心痛点，但图像修复不可控——擦完可能把印刷体也毁了，或者留下灰印。

应对：

  1. 主路径：文本重建——OCR 得到文字，用户在文本框里删掉多余内容，重新排版 → 结果必然干净
  2. 辅助：手动擦除——图形题/公式题保留原图，用户手指涂抹擦掉笔迹
  3. 不做自动擦除（至少在 MVP 阶段）

难点 3：数学公式与图形 ⚠️ 中风险

通用 OCR 认不出公式（x²+2x-1=0 可能变成乱码），图形更不可能重建。

应对：

  • 按区域类型分别处理：文字区 → 文本重建；图形区/公式区 → 保留原图
  • 用户可以在切题时标注"这块是图，别重建"
  • 公式识别作为 P2（需要 Mathpix 之类的专门服务）

难点 4：变式题可能出错题 ⚠️ 中风险

LLM 生成的题可能条件矛盾、答案错误、难度不符。

应对：

  • 生成的题必须人工确认才入库
  • 提供"重新生成"按钮
  • 界面上明确标注"AI 生成，请核对"

难点 5：打印版式

不同题型（纯文字 / 含图）在 A4 上的排版不一致。

应对：

  • 统一用"题目卡片"排版：题干 + 预留答题空间
  • 图片题按比例缩放，限制最大高度
  • 先做简单版式，后续再提供模板

八、分阶段计划（提案）

阶段一：能用（MVP）

目标：走通"拍照 → 得到干净题目 → 打印"的完整链路

  • 拍照 / 相册导入
  • 手动框选切题
  • OCR 识别文字
  • 编辑文本 → 重排成干净题目
  • 错题库列表 + 多选
  • 导出 PDF + 系统打印

先不做：自动切题、变式题、手动擦除、标签统计

阶段二：好用

  • 自动预切题 + 手动调整
  • 手动擦除笔迹
  • 生成变式题（接入 LLM）
  • 学科 / 标签 / 掌握状态
  • 搜索

阶段三：长期

  • 复习计划与提醒
  • 错题统计（知识点分布、趋势）
  • 常用练习卷模板
  • 数据备份 / 多设备同步

九、需要你确认的问题

1. 技术栈

  • Flutter 可以吗？ 你已有完整工具链，能直接复用。若你想用原生 Kotlin 也可以，但要从零配环境。

2. OCR 方案

  • 本地 PaddleOCR（离线、免费、隐私好，但 APK 会增大约 20–40MB）
  • 还是云端 OCR API（更准，但照片要上传 + 按次收费）
  • 我倾向本地。

3. 变式题用哪个大模型

需要联网 + API key。你有偏好吗？

  • DeepSeek（便宜、中文好）
  • 通义千问 / 豆包 / 智谱
  • 或者先不做变式题，放到阶段二

4. 手写擦除怎么做

  • A：文本重建（我推荐）—— 干净可靠，但含图形/公式的题会丢
  • B：手动涂抹 —— 保留原貌，但要手动操作
  • C：两者都要 —— 用户按题型选

5. 你孩子的年级 / 主要学科

这会影响：

  • 题型的侧重（低年级数学多图形，高年级多公式）
  • OCR 模型的难度
  • 变式题的提示词设计

6. 一个我不确定的点

你说"拍照然后一键生成错题集"——"一键"到什么程度？

  • 理解 A：拍完自动切题、自动识别，用户只需确认（追求省事，但准确率会有折扣）
  • 理解 B：拍完自动处理，但每道题都让用户检查/微调（慢一点，但结果可靠）

我倾向 B，因为切题和去笔迹都不可能 100% 准，全自动会让家长反复返工、更烦。但这取决于你的偏好。
