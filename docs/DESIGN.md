> 状态：**设计已定稿，待开发**
> 相比 v0.1：已确定全部技术选型，新增**多孩子 Profile**与**待确认环节**，
> 并核实了 DeepSeek 的多模态能力（决定了「图形用 LLM 生成」是否可行）

## 一、这个 App 解决什么问题

孩子做完作业或试卷后，错题散落在纸上。想整理成错题集通常要**手抄一遍**——费时、字丑、还容易抄错。

> **拍几张照片 → 自动切出每道错题 → 去掉孩子写过的笔迹，还原成干净的新题 → 挑出来排版打印。**

核心价值是**省掉手抄**，并且能**反复重做**。

### 目标用户

| 角色 | 用法 |
|---|---|
| **家长**（主要用户） | 拍照、确认、挑题、打印 |
| 孩子 | 做打印出来的练习卷 |

**家里有两个孩子**（二年级、四年级），所以**必须支持多 Profile**，两人的题目绝不能混。

## 二、多孩子 Profile（核心设计）

这是 v0.2 新增的**一级设计**，不是附加功能。

```
Profile（孩子）
├─ id
├─ 姓名 / 昵称
├─ 年级            二年级 / 四年级（影响 AI 出题难度）
├─ 头像（可选）
└─ 创建时间
```

### 规则

| 规则 | 说明 |
|---|---|
| **题目必须归属某个 Profile** | `Question.profileId` 是必填外键，不存在「无主」的题 |
| **全局只有一个「当前 Profile」** | 顶部可随时切换，切换后整个 App（列表、打印、AI 提示词）都跟着变 |
| **不提供「全部孩子」视图** | 避免一张卷子混进两个孩子的题。要合并打印，必须显式选择 |
| **拍照时先选孩子** | 录入流程的**第一步**就是确认「这是谁的题」，默认当前 Profile |
| **练习卷也归属 Profile** | 生成后孩子姓名会印在卷子上（可关） |

> 数据隔离做到**存储层**：所有查询都带 `profileId` 条件，而不是在界面层过滤。
> 这样漏掉过滤的代价是查询报错，而不是悄悄把两个孩子的题混在一起。

### 年级的作用

年级不只是个标签，它直接进入 AI 提示词：

- **二年级**：100 以内加减法、表内乘除、认识钟表/人民币、简单图形
- **四年级**：四则运算、运算定律、角度/平行垂直、三角形、条形统计图、小数

同一道题在不同年级的「变式题」难度不同。**年级是变式题生成的关键参数。**

## 三、核心流程

```
① 选孩子（默认当前 Profile）
        ↓
② 拍照 / 相册导入
        ↓
③ 自动处理（后台）
   ├─ 版面分析 → 自动切出 N 道题
   ├─ OCR 识别题干文字（本地或云端，按设置）
   ├─ AI 重绘图形 / 公式（deepseek-flash 看图）
   └─ 自动分类：学科、知识点、难度
        ↓
④ 待确认列表  ★ 关键环节
   ├─ 逐题预览：原图 ↔ 重建结果 对照
   ├─ 可编辑：改文字、换图形方案、改学科/标签、合并/拆分题目
   ├─ 逐题「通过」或「丢弃」
   └─ 【全部通过】一键确认
        ↓
⑤ 确认后才真正入库（错题库）
        ↓
⑥ 错题列表：筛选 + 手动选择 / 多选 / 全选
   └─ 可在此生成变式题并加入选择
        ↓
⑦ 排版预览 → 一键打印（或导出 PDF）
```

> **④ 是这个设计的核心安全阀**。自动处理一定有错，所以处理结果先进「待确认」，
> 只有用户点过确认的题才进错题库。这样错题库里永远是可信的。

## 五、数据模型

```
Profile（孩子）★ 一级实体
├─ id, 姓名, 年级, 头像, 创建时间
└─ 所有业务的根

Question（错题）
├─ id
├─ ★ profileId          必填，决定归属
├─ 题干文本             OCR + 人工编辑后的结果
├─ 题干元素[]           文字段 / 图形段 / 公式段（见下）
├─ 原始裁剪图路径        切题时裁下的原图，永远保留
├─ 图形处理方式          keepOriginal | aiRedrawn
├─ 学科 / 知识点标签[] / 难度
├─ 来源（哪张卷子）/ 来源照片 id
├─ 掌握状态 / 复习次数 / 创建时间
└─ 变式题关系[]

QuestionElement（题干的组成单元）
├─ 类型                 text | figure | formula
├─ 文字内容             type=text 时
├─ 图片路径             type=figure 时的原图裁剪
├─ SVG / LaTeX 源码     AI 重绘后的结果
├─ 采用的方案           original | ai
└─ 顺序                在题干中的位置

IntakeBatch（一次录入）★「待确认」的载体
├─ id, profileId, 创建时间
├─ 来源照片[]
└─ 状态                 processing | reviewing | done

DraftQuestion（待确认的题）
├─ id, batchId
├─ 原始裁剪图
├─ 自动处理结果（文字 / 图形 / 公式 / 建议分类）
├─ 用户编辑后的版本
└─ 审核状态             pending | accepted | discarded

Worksheet（练习卷）
├─ id, profileId, 名称
├─ 题目列表[] + 顺序
├─ 版式设置
└─ 导出 PDF 路径
```

## 六、技术选型

| 项 | 选择 |
|---|---|
| **框架** | **Flutter**（已确认） |
| 平台 | Android（minSdk 26） |
| 状态管理 | Riverpod |
| 本地存储 | SQLite（`drift`）+ 图片文件 |
| 打印 | `pdf` + `printing` |
| SVG 渲染 | `flutter_svg` |

### OCR：双引擎，用户可选（已确认）

```dart
abstract class OcrEngine {
  String get id;
  Future<OcrResult> recognize(Uint8List image);   // 文字 + 版面块
}

class LocalPaddleOcrEngine implements OcrEngine { ... }   // PaddleOCR，离线
class CloudOcrEngine implements OcrEngine { ... }         // 云端 API
```

| 引擎 | 优点 | 缺点 |
|---|---|---|
| **本地 PaddleOCR** | 离线、免费、**照片不出设备**、无按次费用 | APK 增大约 20–40MB；识别率略低 |
| **云端 OCR** | 识别率更高、包体小 | 照片要上传（隐私）、按次收费、需联网 |

**设置里让用户选**，并在界面上明确写出隐私代价：

> 云端 OCR 会把题目照片上传到第三方服务。题目里可能有孩子的姓名、学校、班级。

### AI：DeepSeek（已确认）

用官方 API（`https://api.deepseek.com`），两个用途：

| 用途 | 模型 | 说明 |
|---|---|---|
| **图形 / 公式重绘** | `deepseek-flash` | **多模态**，直接看裁剪出来的图形区域 |
| **变式题生成** | `deepseek-chat` 或 `deepseek-flash` | 输入题干 + 年级 + 知识点 |

> **已核实**：`deepseek-flash` 支持图片输入（[官方文档](https://api-docs.deepseek.com/zh-cn/guides/vision/)）。
> 这是「图形交给 LLM 生成」能成立的前提——模型看得见图，不是只靠文字猜。

## 七、题目清理怎么做（重点）

你提到的做法是：**文字用文本重建，图形和公式用 LLM 生成，然后拼装成题目。**
核实 DeepSeek 多模态能力后，这条路可行。下面是具体机制。

### 题干被建模成「元素序列」

```
[文字] "一个长方形的长是 8 厘米，宽是 5 厘米。"
[图形] （原题里那个长方形）
[文字] "求它的周长和面积。"
```

而不是一整块无法拆分的图片。每个元素独立处理，最后**拼装**回一道完整题目。

### 三类元素分别怎么处理

| 元素 | 处理方式 | 可靠性 |
|---|---|---|
| **文字** | OCR 识别 → 用户可编辑 → **重新排版** | 高 |
| **公式** | OCR 出文字 → LLM 转 **LaTeX** → 排版渲染 | 高（公式是纯文本，转换稳定） |
| **图形** | 裁剪原图 → 交给 `deepseek-flash` 重绘成 **SVG** | 中（见下） |

### 图形重绘的机制

```
裁剪出的图形区域
     ↓  以 base64 传给 deepseek-flash
     ↓  提示词：识别图形内容，输出等价的标准 SVG（黑白线稿，适合打印）
     ↓
SVG 源码 → flutter_svg 渲染 → 嵌入题目
```

**为什么选 SVG 而不是让 AI 生成图片**：DeepSeek 的接口是对话补全，
输出的是**文本**。SVG 正好是「文本形式的图」，可以精确排版、无限缩放、打印清晰。

### 风险与应对（重要）

⚠️ **AI 重绘的几何图可能与原题不完全一致**——角度、标注、比例都可能偏。

**应对**：

1. **默认不重绘**，图形一律裁剪保留原图。AI 重绘是**用户主动点**的按钮。
2. **强制对照**：重绘后左右并排显示「原图 / AI 重绘」，用户**看过才能选用**。
3. **打印时标记**：使用 AI 重绘的题，在卷子角落标一个小记号，提示家长核对。
4. **公式优先**：公式走 LaTeX（可靠），只有图形才需要重绘——**缩小风险面**。

> 换句话说：**AI 重绘是「可选增强」，不是默认路径。**
> 默认路径（保留原图）永远是对的，只是可能带着笔迹。

### 成本（Token 机制）

已核实（[官方文档](https://api-docs.deepseek.com/zh-cn/guides/vision/)）：

- 每张图片按尺寸换算 token，**上限 1024 token**
- 图片会被自动缩放到约 1300×1300 等效像素
- `detail: low` 会缩到 512×512，更快更省

**推算**：一道含图的题 ≈ 1 张图（≤1024 token）+ 题干文字（几百 token）。
一次录入 10 道题，大概几万 token 量级。具体单价请以官网为准。

**省钱手段**：
- 图形裁剪后**先压缩**再上传（`detail: low` 对简单图形够用）
- 只有**含图形的题**才调用视觉模型，纯文字题不调用
- 用 DeepSeek 的**上下文缓存**（重复的前缀提示词不重复计费）

## 八、技术难点与应对

### 难点 1：自动切题不一定准 ⚠️ 高风险

试卷版面千变万化。全自动切分一定有错。

**应对**：自动切分只作**预切分**，进入**待确认列表**让用户调整（合并/拆分/重框）。
宁可多切几块让用户合并，也不要漏题。

### 难点 2：去掉手写笔迹 ⚠️ 中风险（已降级）

原本是最大风险，因为图像修复不可控。

**已定方案**：**不做图像修复**，走**文本重建 + LLM 重绘**。文字必然干净（是重新排版而不是修图）。

**残留风险**：图形重绘的准确性问题，见第七节。

### 难点 3：数学公式与图形 ⚠️ 中风险

**应对**：公式走 LaTeX；图形走「默认保留原图 + 可选 AI 重绘 + 强制对照」。

### 难点 4：变式题可能出错题 ⚠️ 中风险

LLM 生成的题可能条件矛盾、答案错误、难度不符。

**应对**：生成的题**必须人工确认**才入库；提供「重新生成」；界面标注「AI 生成，请核对」。

### 难点 5：两个孩子的数据不能混 ⚠️ 中风险

**应对**：`profileId` 进数据模型，**存储层过滤**而非界面层；不提供「全部」视图；
拍照流程第一步就确认归属。

### 难点 6：打印版式

不同题型（纯文字 / 含图 / 含公式）在 A4 上的排版不一致。

**应对**：统一「题目卡片」排版；图片按比例缩放限高；先做简单版式。

## 十、分阶段计划

### 阶段一：能用（MVP）

**目标**：走通「拍照 → 确认 → 干净题目 → 打印」

- Profile 管理 + 切换
- 拍照 / 相册导入
- 手动框选切题
- 本地 OCR（PaddleOCR）识别文字
- **待确认列表**：编辑文字、逐题确认、批量通过
- 错题库列表 + 手动选择 / 多选 / 全选
- 导出 PDF + 一键打印
- **图形一律裁剪保留原图**

> 先不做：自动切题、AI 重绘、变式题、云端 OCR、手动擦除、统计

### 阶段二：好用

- 自动预切题
- **AI 重绘图形/公式**（DeepSeek 多模态）+ 对照选择
- **变式题生成**（DeepSeek）
- 云端 OCR 可切换
- 学科 / 标签 / 掌握状态
- 搜索

### 阶段三：长期

- 复习计划与提醒
- 错题统计（知识点分布、趋势）
- 练习卷模板
- 数据备份 / 多设备同步
