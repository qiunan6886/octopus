# Octopus · UX 设计（v1）

> 配合 `DESIGN.md` 阅读。这份讲**长什么样、为什么这样**，那份讲**做什么**。

## 一、视觉概念：纸与墨

两套主题，互为反色，**严格单色**。

| | 纸（浅色） | 墨（深色） |
|---|---|---|
| 背景 | `#F4F4F2` 暖白 | `#000000` 纯黑 |
| 卡片 | `#FFFFFF` | `#0D0D0D` |
| 强调色 | `#111111` **黑** | `#FFFFFF` **白** |
| 正文 | `#121212` | `#FFFFFF` |

### 为什么是单色

这是**错题**应用，屏幕上的主角是试卷照片和印刷体文字。

1. **不抢注意力** —— 任何彩色都会和题目内容竞争。家长要看的是「这道题对不对」，不是导航栏。
2. **打印一致** —— 错题最终要打印出来。屏幕上什么样，纸上就什么样，不会出现「彩色图标打印变灰块」。
3. **切题时的高亮** —— 框选时用强调色画框，在单色底上反而最醒目。

### 唯一的例外：`danger`

删除类操作保留红色（浅色 `#B3261E` / 深色 `#FF6B6B`）。

破坏性操作**必须一眼可辨**，这是安全要求，不是审美偏好。整个应用只有这一处不是灰阶。

### 参考 Spark

沿用 Spark 的设计语言，两个项目的观感才能连上：

- 同一个结构：调色板是数据（`OctopusPalette`）+ 全局静态访问点（`OctopusColors`）
- 同一套尺寸：圆角 `card=20 / sheet=24 / pill=999`，间距 `page=20 / gap=12 / section=28`

**为什么用静态读取而不是 `ThemeExtension`**：绝大多数调用点只关心颜色值本身
（`OctopusColors.accent`），写成 `Theme.of(context).extension<...>()` 会让每个调用点都变长。
代价是 Flutter 观察不到静态值的变化，所以换主题时用 palette id 当 key 强制重建整棵树。

## 二、布局

### 全局

```
┌─────────────────────────────────┐
│ Octopus            [小明 四 ▾]  │  ← 当前孩子，始终可见
├─────────────────────────────────┤
│                                 │
│           页面内容               │
│                                 │
├─────────────────────────────────┤
│  错题库   录入   练习卷   设置    │  ← NavigationBar
└─────────────────────────────────┘
```

### 为什么把「当前孩子」钉在顶部

设计文档定的是「切换后整个应用都跟着变」。既然上下文这么重要，就**必须一直看得见**——
否则家长会往错误的孩子的库里存题，而这种错误很难发现。

孩子选择器是一个 pill：`[头] 小明 四 ▾`，点头像打开底部弹窗切换。

### 为什么「错题库」是第一个标签

设计文档的页面结构里「录入」排第一。实现时把它调到了第二位，理由：

- **错题库是回来的地方，录入是一次性动作**
- 打开应用直接进相机太有攻击性——用户可能只是想看看、想打印

录入依然是第二重要，而且错题库空态里有一个显眼的「去录入」按钮。

### 页面骨架

| 页面 | 结构 |
|---|---|
| **错题库** | 大标题 + 数量 → 筛选 chips → 卡片列表 →（多选时）底部操作条 |
| **录入** | 大标题 → 未完成批次提醒 → 两个大按钮（拍照 / 相册）→ 流程说明 |
| **框选** | 全屏图片 + 拖拽画框 → 底部「撤销 / 完成」 |
| **待确认** | 每道题一张卡：原图 + 可编辑文字 + 三个动作 |
| **练习卷** | 列表 → 预览 → 底部「导出 PDF / 打印」 |
| **设置** | 分组卡片：孩子 / 外观 / 识别 / AI / 打印 / 关于 |

## 三、几个具体决定

### 1. 底部导航不放悬浮按钮

拍照是主操作，但**放 FAB 会挡住列表最后一条**。改成把「录入」做成独立标签页，
里面用两个**通栏大按钮**——手指够得到，且不遮挡任何内容。

### 2. 多选靠长按进入，不靠「编辑」模式

长按任意一行进入多选并选中该行。这比先点「编辑」再勾选少一步。

选中时每行左侧出现圆形勾选框，底部升起操作条：

```
┌──────────────────────────────────────────┐
│ ✕   已选 3 道        全选  🗑  [生成练习卷] │
└──────────────────────────────────────────┘
```

「全选」和「取消全选」是**同一个按钮**切换文案，省一个位置。

### 3. 待确认列表一定要显示原图

每道待确认的题都**并排显示原图和识别结果**。原因：

- 阶段一还没有 OCR，识别结果本来就是空的——不给原图的话用户完全不知道这是什么
- 有 OCR 之后，用户也必须能**对照原文**才能判断识别对不对

### 4. 状态用「点」而不是「标签」

错题卡片左下角是一个 6px 的圆点 + 文字：

- 未掌握 → 强调色（黑/白）
- 复习中 → 次要灰
- 已掌握 → 三级灰

比彩色标签克制，且三个状态在灰阶上就能区分。

### 5. 空态给下一步动作，不给一句「暂无数据」

| 场景 | 文案 + 动作 |
|---|---|
| 没有孩子 | 「先添加一个孩子」+ 说明为什么必须有归属 |
| 错题库为空 | 「还没有错题」+ **[去录入]** |
| 筛选无结果 | 「这个筛选下没有题」+ 换条件试试 |
| 没有练习卷 | 「还没有练习卷」+ **[去错题库]** |
| 框选为空 | 「在照片上拖动，框出一道题」 |

## 四、框选交互

阶段一是**手动框选**（自动切题属于阶段二）。

```
手指在照片上拖动 → 出现半透明遮罩，框内保持原色
松手 → 框固定，右下角计数 +1
可连续框多道 → 点「完成」一次性裁切
```

**关键实现细节**：框用**相对图片的归一化坐标**（0..1）保存，不是相对控件。

因为图片按 `BoxFit.contain` 显示时四周会留边（图片比例和控件比例不一致）。
如果按控件归一化，裁出来的位置会整体偏移——这个 bug 在写的时候差点漏掉。

判断逻辑：

- 拖动起点必须在图片区域内，否则忽略
- 拖出边界时**夹回边界**，而不是丢弃这次拖动
- 松手时框太小（宽 < 3% 或高 < 1.5%）视为误触，丢弃

## 五、可访问性与细节

- 文字全部用相对字号，跟随系统字体缩放
- 深色主题下状态栏图标自动切换明暗，否则会看不见
- 所有图片加载失败都有占位，不留空白
- 按钮最小高度 44–48px，符合触控目标下限
- 危险操作（删除）统一二次确认，且确认按钮是红色
