# Octopus · 错题集

把孩子的错题**拍照 → 切题 → 还原成干净的新题 → 挑题排版打印**，省掉手抄。

> **当前状态：阶段二完成。**
> 已实现：多孩子隔离、三套主题（纸/墨/彩）、拍照/相册录入、**自动切题**、
> 手动框选调整、**本地 OCR**、**拍照批改**、**AI 重绘去笔迹**、**变式题**、
> 待确认环节、错题库多选、生成练习卷、导出 PDF / 打印。
> **还没实现**：中英双语、复习计划与提醒、错题统计。

## 三个 AI 功能

都在题目详情页（错题库 → 点开一道题）里。

### 自动切题

在框选页点「自动切题」，用 ML Kit 的文字块坐标把整页切成题。

两条路径：**按题号切**（找到 ≥2 个题号行，最准，因为题号是作者自己划的边界）；
没有题号时**按空白切**（用行距的下四分位当基准，间距明显更大的地方断开）。

只作**预切分**——切完照样能手动增删改框。

### AI 重绘（去掉笔迹）

把孩子做过、有涂改勾叉的题交给 `deepseek-flash`，重画成一张干净的 SVG。

**为什么是 SVG**：模型只能输出文本，而 SVG 正好是「文本形式的图」，两边都能用——
屏幕用 `flutter_svg` 显示，打印用 `pdf` 包的 `pw.SvgImage` 直接嵌进 PDF。位图做不到这点。

**必须对照才生效**：模型会画错，所以重绘结果存下来但**默认不选中**，
界面上并排显示「原图 / AI 重绘」，用户点过「用这张」才会印出去。

### 变式题

选中一道题生成同知识点、同难度的新题（换数字、换情境），可逐题修改，
**确认后才入库**，并记住来源题。

有题干文字就走文字（便宜、准）；没文字就把图片发过去。

## 三套主题

| 主题 | 说明 |
|---|---|
| **纸**（默认） | 暖白底 + 纯黑强调色 |
| **墨** | 纯黑底 + 纯白强调色，和纸互为反色 |
| **彩** | 淡紫底，紫 + 珊瑚双强调色，头部渐变，学科标签按科目上色 |

**单色是默认**——屏幕主角是试卷照片，彩色会和题目抢注意力，打印时也会失真。
「彩」是给想换个心情的用户的可选项。

彩主题不只是在单色上加一个强调色：它还带了第二强调色、成功色、警告色和头部渐变，
并且**这些东西真的出现在界面上**（渐变标题、渐变头像、彩色学科标签、按状态变色的掌握圆点）。
为了不写一堆 `if (vivid)`，单色主题里 `accentAlt == accent`、渐变两端同色、
`subjectColor()` 返回中性灰，两套主题走同一条代码路径。

`test/theme_test.dart` 守住几条容易被静默破坏的规则：纸墨互为反色、彩色不渗透单色主题、
学科配色稳定、彩主题的对比度仍然达标。

## 数据备份

**这是这个应用里唯一不可逆的失败模式**：孩子的错题、照片、批改记录全都只存在这台
手机上。手机丢了、重置了、卸载了，几个月的积累就没了。

设置 → 数据备份：

- **导出备份** —— 打包数据库 + 全部图片 + 一份清单，通过系统分享发到微信 / 网盘 / 邮箱
- **从备份恢复** —— 选一个 zip，先看清里面是什么，二次确认才覆盖

### 恢复时必须重写图片路径

数据库里存的是**绝对路径**（`/data/user/0/com.mossapps.octopus/.../q_1.jpg`）。
换台设备、甚至同一台重装之后，这个路径就不存在了。所以恢复时只保留**文件名**，
目录换成本机的。

**漏掉这一步的后果是**：图片文件明明就在旁边，点开每道题却都是空白。测试里专门
有一条端到端断言盯着这件事——导出到 A 目录、恢复到 B 目录，然后验证数据库里的路径
指向 B 且 `File(...).existsSync()` 为真。

为了让人漏不掉，`restore()` 把「关数据库」和「重开后修路径」做成了**必填回调**，
顺序由服务保证（关库 → 落图片 → 换数据库 → 重开并改路径）。写成文档一定会有人漏，
做成必填是编译不过。

> 替换数据库文件前必须先关连接：sqflite 持有打开的文件句柄，直接覆盖会让连接
> 读到半新半旧的页。

### 备份用一致性快照，不直接读活库

导出时走 `VACUUM INTO` 而不是复制文件。SQLite 在写入过程中文件处于中间状态，直接
读字节可能拿到半个事务，备份出来的库打不开。

### 导入前先校验

zip 里有 `manifest.json`（应用标识 + schema 版本 + 条目数）。导入前先读它，拒绝：
不是 Octopus 的备份、来自更新版本（老代码读不懂新表结构）、清单损坏。没有这道校验
的话，用户随手选错一个 zip 就可能把数据库覆盖成垃圾。

## 复习计划

**收题只是手段，让孩子重做才是目的。** 所以每道错题入库时就排好了复习时间。

间隔重复节奏：**1 → 3 → 7 → 14 → 30 天**，走完 5 次算掌握。

- 错题库顶部有「**今日待复习 N 道**」的入口，一点就筛出来
- 每张卡片上直接写「今天该复习 / 3 天后复习」，家长看一眼就知道要不要动手
- 做成练习卷后，Snackbar 上给一个「**标记为已复习**」动作推进计划

**为什么打印完不自动推进**：打印不等于孩子做完了。让家长在孩子做完之后点一下，
复习计划和实际进度才对得上。

**掌握状态可以手动改**——自动推进依据的是「复习次数」，那只是个代理指标。真正
该看的是孩子每次重做对不对，但那需要把重做后的照片再批改一遍并关联回原题，现在
做不到。所以家长随时能手动标回未掌握。

纯间隔逻辑在 `lib/services/review_schedule.dart`，不读时钟也不碰数据库，另有
`test/review_schedule_test.dart` 覆盖时间边界。

## OCR：本地 / 云端可选

在**设置 → 识别**里切换，另有一个「切题后自动识别」开关（默认开）。

| 引擎 | 用什么 | 优点 | 缺点 |
|---|---|---|---|
| **本地**（默认） | Google ML Kit | 离线、免费、**照片不出设备** | APK 约 32MB；读不了手写体 |
| **云端** | DeepSeek 视觉模型 | 能读手写体、理解版面、公式转 LaTeX | 照片要上传、按次收费 |

本地是默认，因为题目照片里常有孩子的姓名、学校、班级。**没配 API Key 时选云端
会自动回退到本地**——拍照录入是主流程，不该因为一个可选配置卡住。

> 中文模型**打包进了 APK**（`com.google.mlkit:text-recognition-chinese`），
> 不是首次使用时下载。代价是 APK 大 13MB，换来的是开箱即用、真离线。

## 拍照批改

**批改和录入是同一条流程，不是两个功能。** 「错题」的定义就是做错的题——只要能
判断对错，错题库就能自动筛出来。

在**设置 → 批改**里开关，默认关：

| 设置 | 默认 | 说明 |
|---|---|---|
| 拍照后批改 | 关 | 打开后流程里多一步判断对错 |
| 用 AI 批改 | 开 | 关掉或没配 Key 时，自己点「做对了 / 做错了」 |
| 做对的题也入库 | 关 | 默认只留错题 |

**AI 批改**把切出来的那道题（含孩子的手写答案）发给 `deepseek-flash`，**一次调用**
拿到对错、正确答案、判断理由、学科和知识点。**手动批改**完全离线，点一下就行。

两种方式的结果都**只是建议**：确认页每题都能改对错、改正确答案，AI 的判断带 `AI`
标记，一眼能看出哪些需要复核。

### 判断理由会展示出来

只给一个「错」字，家长没法判断是孩子错了还是模型看错了。所以 AI 必须给出具体的
依据（「竖式第二行忘了进位」而不是「算错了」），这句话会显示在确认页和错题详情里。

### 学科和知识点是批改时顺手识别的

模型本来就在看题目，所以同一次调用让它标出学科和知识点。有了这个：

- 错题库的学科标签才有内容（彩主题下按科目上色）
- 才谈得上**按学科统计正确率**

### 批改统计

错题库右上角点图表图标进入。

**口径是「批改过的题」，不是「入库的题」**——做对的题默认不进错题库，但它们同样是
批改结果。只统计 `questions` 表的话正确率永远是 0。所以统计走 `draft_questions`。

页面给出：总体正确率、按学科正确率、以及 **AI 判断被手动改过的比例**（用来看 AI
可不可信）。

> 为什么不比对答案：题目和答案都是手写的，题型又五花八门，要比对得先有标准答案，
> 而这里没有。视觉模型能同时看见题干和孩子的答案，直接判断。

## 三个关键设计判断

1. **不做图像修复去笔迹**，改用**文本重建** —— 把印刷体 OCR 出来重新排版，
   结果必然干净；含图形/公式的区域保留原图，可选让 `deepseek-flash` 重绘成 SVG
2. **不做全自动** —— 自动切题和去笔迹都不可能 100% 准，所以有「待确认」环节，
   用户确认后才入库，避免家长反复返工
3. **照片默认不出设备** —— 默认用本地 OCR；切到云端 OCR 时界面会明确提示
   照片会上传到第三方

## 两个孩子的数据隔离

这是整个项目最容易出、后果最严重的一类错误——把老二的题打进老大的卷子。

所以隔离做在**存储层**，不是界面层：

- `profileId` 是必填外键，不存在「无主」的题
- **所有**读写题目的方法都要求传 `profileId`（`deleteQuestions`、`setMastery` 也一样）
- **不提供**「全部孩子」视图
- 拍照流程第一步就确认归属

`test/data_isolation_test.dart` 对着真实 SQLite 验证这些保证，8 个测试覆盖到
「用错的身份删不到别人的题」这种反向场景。

### 为什么是 sqflite 而不是 drift

设计阶段选的是 drift。实际搭建时遇到死结：

- drift 2.32+ 依赖的 `sqlite3` 3.x 会在**编译时从 GitHub 下载**预编译的
  SQLite 库，网络不通就整个构建失败
- 想降级到用 `sqlite3` 2.x 的旧版 drift，又与新版 `build_runner` 的
  analyzer 版本要求冲突，解不开

sqflite 直接用 Android 系统自带的 SQLite，**没有原生资源、不需要联网**，
构建永远可复现。代价是失去编译期的查询检查，用「所有方法必须传 profileId」
这条纪律补回来。

## 已踩过的坑（都有测试兜住）

| 坑 | 后果 | 兜法 |
|---|---|---|
| SQLite 默认不开外键约束 | `ON DELETE CASCADE` 形同虚设，删掉孩子留下一堆孤儿题 | `onConfigure` 里 `PRAGMA foreign_keys = ON`，测试验证 |
| 框选按控件归一化 | 图片 `BoxFit.contain` 留边时，裁出来的位置整体偏移 | 按**相对图片**的归一化坐标存 |
| 改 schema 不写迁移 | 老用户升级后新字段不存在，读写直接崩 | `onUpgrade` 加列，`test/migration_test.dart` 用真实的 v1 库验证 |
| ML Kit 只打包中文模型 | R8 找不到其他语种的识别器，release 构建直接失败 | `proguard-rules.pro` 里 `-dontwarn` 那些包 |
| PowerShell 往返读写中文文件 | 文件变乱码且被提交 | 不用 PowerShell 读写中文文本；`tools/check_encoding.py` 做**往返检测** |
| Bash 控制台把 UTF-8 当 GBK 显示 | 中文看起来像乱码，误判成文件损坏 | 用 Python `repr` 看真实字符，不信控制台渲染 |
