Add OCR, completing the capture-to-clean-question loop

Local OCR uses Google ML Kit's on-device Chinese recogniser; cloud OCR uses
DeepSeek's vision model. Chosen in Settings, with an extra switch for running
recognition automatically after cropping (on by default).

Local was going to be PaddleOCR, which needs tens of megabytes of detection and
recognition weights and a hand-written detect/recognise/merge pipeline. ML Kit
ships the Chinese model as a Gradle dependency, so bundling it costs 13 MB and
the app is genuinely offline. It also fits the job: the text being recognised is
the printed question, not the child's handwriting -- that is the grader's
problem, and ML Kit reads print well and handwriting badly.

The Chinese model is bundled rather than fetched on first use, because otherwise
offline operation would only hold if the device has Play Services and a network
at that moment. Selection falls back to local when the cloud engine is chosen but
no API key is set: capture is the main flow and should not be blocked by an
optional setting.

Recognition runs per crop during intake, so failures are reported per question
and a failure never loses the crop -- the draft is still created and the text can
be typed in or recognised later from the review screen.

Shared the DeepSeek HTTP plumbing out of the grader into deepseek_client.dart,
since grading and cloud OCR are both one image plus one instruction.

R8 failed the release build because the ML Kit plugin references every script
recogniser while only Chinese is bundled; proguard-rules.pro marks those packages
as allowed to be missing.

Verified: analyze clean, 29 tests pass, release APK builds for all three ABIs.
